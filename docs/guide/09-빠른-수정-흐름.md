# 빠른 수정 흐름 - 계획 (2026-10-28, 2편 시작할 때 만든다)

사용자: "수정 요청을 구조화하고 저화질로 주면서 시간을 단축시키는 것도 생각하자" → "엉 저장해"
아직 만들지 않은 **계획**이다. 2편 시작할 때 `scripts/preview.py`부터 만들어 쓴다.

## 왜 (1편 다시 만들 때 시간·토큰이 든 곳)
1. 수정 요청이 하나씩 와서, 하나 고칠 때마다 렌더하고 확인했다 (같은 장면을 여러 번 왕복)
2. 고친 곳만이 아니라 전체 360p(약 25분 + 마무리)를 자주 다시 렌더했다
3. Claude가 프레임 사진을 열어 보는 확인이 많았다 (같은 장면을 여러 번)
- 렌더 자체는 토큰이 안 든다. 토큰은 장면 코드를 짜고 고치고, 사진으로 확인하는 데 든다

## 1. 수정 요청 한 장으로 모으기
- 미리보기를 줄 때 `수정 요청.md`를 같이 준다 (미리보기 옆에). 사용자는 보면서 한 줄씩:
  ```
  시간 | 무엇이 | 어떻게
  1:58 | 오른쪽 화면 깜빡임 | 고쳐
  9:47 | 진영 → 지도 넘어갈 때 뚝 끊김 | 서서히
  10:55 | "제가 시작한 게 아닙니다" | "몽골이 시작한 게 아닙니다"로
  ```
- Claude는 모인 요청을 한 번에 고치고 한 번만 렌더해서 준다. 급한 건 지금처럼 바로 말해도 된다
- 요청마다 고친 결과를 같은 표에 `→ 고침: …` 한 줄로 적어 돌려준다 (무엇을 어떻게 고쳤는지 한눈에)

## 2. 고친 곳만 저화질로: `scripts/preview.py` (만들 것)
- 입력: 대사 번호(`c5_17`) 또는 시간대(`9:30-9:45`)
- 하는 일 (1편 때 손으로 하던 것을 하나로):
  1. 대사 번호 → 프레임 구간 (draft-final.py 타임라인 계산과 같은 식)
  2. 전체 길이가 바뀌었으면(대사 길이 변화) 그 지점부터 끝까지, 아니면 그 구간만 360p 렌더 - **동시 렌더 2개까지** (4개면 오른쪽 띠 깨짐, 04 사고 기록)
  3. 깨진 프레임(타일·띠·튀었다 돌아옴) 찾아 한 장씩 다시 찍기
  4. 직전 미리보기 프레임에 끼워 넣기 + 소리 두 갈래 다시 섞기(stem-mix.py) + -14 LUFS
  5. 전체 미리보기 갱신 + **바뀐 구간만 짧은 영상** 따로 (오늘 무칼리·기도 대사처럼 "그 부분만 보기")
  6. 하네스(check-draft --video, check-bgm-cut) 돌리고 결과 한 줄, 바로 띄움
- 1440p 본편은 지금처럼 마지막에 한 번 (유튜브 마감 순서: 한국어 360p 확인 → 영어 1440p → 업로드)

## 3. Claude의 확인 방식
- 프레임 사진을 열어 보기 전에 하네스 숫자로 먼저 판단한다
- 사진은 하네스가 잡은 곳, 처음 만든 장면, 사용자가 짚은 곳만 본다. 같은 장면을 여러 번 사진으로 확인하지 않는다
- 재사용 장면 부품을 쌓는다 (1편: 진격, 궁궐, 섬, 천막 회의, 산 기도 등) → 2편부터 새로 짜는 양을 줄인다

## 예상
| | 1편 | 바꾼 뒤 |
|---|---|---|
| 대사 하나 고치고 확인 | 전체 360p 약 25분 + 마무리 | 그 구간만 약 2~4분 |
| 수정 요청 5개 | 5번 왕복 | 1번에 처리 |
